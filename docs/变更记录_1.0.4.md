### 2.8 开屏竞价

**功能说明**：冷/热启动时同时请求开屏广告和插屏广告，展示 eCPM 更高的广告。

| 场景 | 预期结果 |
|------|----------|
| 两个广告都加载成功 | 展示 eCPM 更高的广告 |
| 仅开屏广告加载成功 | 展示开屏广告 |
| 仅插屏广告加载成功 | 展示插屏广告 |
| 两个广告都加载失败 | 直接进入 APP，不卡顿 |
| 加载超时（超过配置的 splash_time_out） | 检查当前缓存状态，有则展示，无则进入 APP |
| 竞价加载超时后 | 取消未完成的加载任务，竞价结束后不应再出现“开屏/插屏加载成功/失败”等日志污染 |
| 关闭竞价开关（splash_bidding_enabled=0） | 回退到传统模式，只请求开屏广告 |
| 新用户需要通知权限授权 | 授权完成后才开始超时计时，授权期间不计入超时 |
| 权限流程回调异常/丢失 | 启动页权限流程兜底，不应卡死在等待状态（最终可继续进入 APP） |
| eCPM 取价缓存为空 | 返回 N/A，不应为了取价触发额外加载请求 |

**验证日志**（Logcat 过滤 `SplashBidding|AdmobReflection|竞价`）：

| 日志关键词 | 含义 |

| `[SplashBidding] 开始加载插屏广告...` | 插屏请求开始 |
| `[SplashBidding] 竞价加载超时` | 竞价加载超时分支触发（后续将检查缓存并结束竞价） |
| `[竞价] 获取开屏广告价格成功: X.XXXXXX` | 开屏 eCPM 获取成功 |
| `[竞价] 获取插屏广告价格成功: X.XXXXXX` | 插屏 eCPM 获取成功 |
| `[SplashBidding] 竞价结果：开屏胜出` | 开屏广告胜出 |
| `[SplashBidding] 竞价结果：插屏胜出` | 插屏广告胜出 |
| `[SplashBidding] ========== 竞价结果汇总 ==========` | 竞价结果汇总 |
| `开屏竞价结果 -> 开屏:` | 竞价结果埋点日志（用于上报） |
| `等待权限授权完成后开始超时计时...` | 等待权限授权 |
| `权限授权完成，开始超时计时` | 权限完成，超时计时开始 |
| `[权限] 重置权限拦截器` | 每次启动页启动会重置权限拦截器，避免复用旧状态 |
| `[权限] 权限授权完成，取消拦截` | 权限流程结束，解除广告展示等待 |

| `启动页通知授权流程超时兜底` | 权限流程超过兜底时间仍未回调，强制推进流程防卡死 |

- `splash_bidding_enabled`: 竞价开关（1=启用，0=禁用）
- `splash_time_out`: 竞价超时时间（秒）

### 2.9 激励三方竞价

**功能说明**：在激励点位触发时，同时请求激励广告（A）、插页激励广告（B）、插屏广告（C），在超时时间内比较展示前 eCPM，展示 eCPM 更高的广告。

**补充说明**：当竞价结果为“插屏胜出”时，走专用的竞价插屏展示入口：
- 跳过插屏 cooldown 校验
- 不更新插屏配置的 `lastShow/dailyShow`（避免影响普通插屏频控统计）
- 强制 `ignoreFullNative=true`

| 场景 | 预期结果 |
|------|----------|
| 5s 内 A/B/C 多个加载成功 | 比较 eCPM，展示 eCPM 最大者 |
| 5s 内仅一个加载成功 | 直接展示该广告 |
| 5s 内 A/B/C 全失败 | 直接进入下一页面 |
| 竞价超时（> reward_bidding_time_out） | 取消未完成加载任务；检查缓存状态，有则参与比价展示，无则进入下一页面 |
| 失败的广告 | 缓存保留，下次竞价优先复用缓存（避免额外请求） |
| 广告过期 | 重新请求新广告后再参与竞价 |
| 插屏胜出后展示插屏 | 可正常展示插屏；跳过 cooldown 校验；且不应更新插屏 `lastShow/dailyShow` |
| 插屏胜出后再触发普通插屏展示 | 普通插屏仍按自身频控逻辑执行（因竞价插屏不更新 `lastShow/dailyShow`） |

**同 eCPM 的选择规则**：当 eCPM 相同或非常接近时，优先级可能与之前版本不同，需补充覆盖“同价时会选哪种广告类型”的回归验证。

**对外入口**：`FragmentActivity.loadRewardBidding { success -> ... }`

**验证日志**（Logcat 过滤 `RewardBidding|AdmobReflection|竞价`）：

| 日志关键词 | 含义 |
|------------|------|
| `[RewardBidding] ========== 开始激励三方竞价加载 ==========` | 竞价开始 |
| `[RewardBidding] 超时时间: 5000 ms` | 当前竞价超时配置（由 reward_bidding_time_out 秒配置换算而来） |
| `[RewardBidding] 开始加载激励广告...` | A 请求开始 |
| `[RewardBidding] 开始加载插页激励广告...` | B 请求开始 |
| `[RewardBidding] 开始加载插屏广告...` | C 请求开始 |
| `[RewardBidding] 竞价加载超时` | 进入超时分支（后续会检查缓存并结束竞价） |
| `[RewardBidding] 竞价正在进行中，忽略本次请求` | 防并发：竞价进行中时忽略重复触发 |
| `[竞价] 获取激励广告价格成功:` | A eCPM 获取成功 |
| `[竞价] 获取插页激励广告价格成功:` | B eCPM 获取成功 |
| `[竞价] 获取插屏广告价格成功:` | C eCPM 获取成功 |
| `[RewardBidding] 插屏胜出 -> 走竞价插屏入口（跳过cooldown，不更新lastShow/dailyShow）` | 插屏胜出时的展示入口日志 |
| `[RewardBidding] 竞价插屏入口: 跳过cooldown校验且不记录lastShow/dailyShow` | 竞价插屏入口的关键参数输出 |
| `[RewardBidding] 竞价插屏recordShow: 已跳过（不更新dailyShow与lastShow）` | 竞价插屏展示时已跳过插屏频控统计更新 |
| `激励竞价结果 -> 激励:` | 竞价结果埋点日志（用于上报） |

**配置项**（`ad_config.json`）：
- `reward_bidding_enabled`: 激励竞价开关（1=启用，0=禁用，关闭时回退普通激励广告）
- `reward_bidding_time_out`: 激励三方竞价超时时间（秒，默认 5，内部换算为毫秒）

## 5. 已知风险

| 风险 | 说明 |
|------|------|
| 天气通知多机型兼容 | 不同 ROM 对 RemoteViews 处理有差异，需多机型验证 |
| 关闭按钮开关 | 默认可能为启用状态，需确认远程配置 |
| 开屏竞价反射路径 | 依赖 AdMob SDK 版本（当前 0.22.0-beta04），SDK 升级后可能需更新反射路径 |
| 开屏竞价结果埋点口径 | 展示前 eCPM 取值为反射值，仅用于“策略选择/日志验证”，不等同于最终 onAdPaid 实际收益（需与数据/广告策略同学确认口径） |
