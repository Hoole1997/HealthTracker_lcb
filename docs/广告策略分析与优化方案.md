# HealthTracker 广告策略分析与优化方案

> 基于 AdMob 收益核减问题的深度分析与解决方案  
> 创建时间：2026年1月6日

---

## 📋 执行摘要

根据 AdMob 收益核减机制分析，当前 HealthTracker 应用存在多个**高误触风险**的广告触发场景，预估核减率可能达到 **15-25%**。本文档提供了系统性的问题识别和优化方案，预期可将核减率降低至 **5-10%** 的正常范围。

**核心问题**：广告触发时机过于激进，违反了"用户明确操作后展示"的最佳实践。

**优化原则**：从"页面生命周期驱动"改为"用户行为驱动"的广告策略。

---

## 🔍 问题分析

### 理论基础：AdMob 核减机制

根据核减问题讨论文档，AdMob 收益核减的核心原因包括：

1. **无效流量**：误触、重复点击、非正常行为
2. **广告主拒付**：不满足结算条件的曝光
3. **政策瑕疵**：广告加载但不可见、遮挡、未符合展示规范
4. **系统修正**：算法更正

**关键洞察**：
- 核减 ≤ 5%：正常范围
- 5%～15%：需要警惕，广告体验或流量质量有问题
- \>15%：基本确定广告位设计、触发时机或用户行为结构出问题

### 🔴 高风险问题识别

#### 1. 返回键必弹插屏（BaseInterActivity）

**问题代码**：
```kotlin
// BaseInterActivity.kt:24-35
override fun handleBackPress(): Boolean {
    showInter {
        trackBackEvent()
        finish()
    }
    return true
}
```

**风险分析**：
- 所有继承 `BaseInterActivity` 的页面返回键都触发插屏
- 属于"返回动作里弹出广告"的典型误触场景
- 用户在退出意图中被迫看广告，广告主不认可此类点击

**影响页面**：
- HealthRecordScreen（记录页面）
- HealthStatisticsScreen（统计页面）
- HealthDetailScreen（详情页面）
- 其他继承 BaseInterActivity 的页面

#### 2. 页面进入即弹插屏

**问题代码**：
```kotlin
// HealthStatisticsScreen.kt:147
override fun initView(savedInstanceState: Bundle?) {
    // ...
    loadInterstitial {  }  // 页面初始化就加载插屏
}
```

**风险分析**：
- 违反"首屏还没稳定就加载广告"原则
- 用户注意力未稳定、页面结构未静止时展示广告
- 属于"薛定谔的点击"场景

#### 3. 开屏失败自动降级插屏

**问题代码**：
```kotlin
// LaunchAds.kt:314-319
return if(AdConfigManager.shouldShowInterstitialAfterAppOpenFailure()){
    AdsManager.Controllers.interstitial.displayAd(
        activity,
        BuildConfig.ADMOB_INTERSTITIAL_ID
    )
} else interceptResult
```

**风险分析**：
- 开屏广告失败后立即尝试插屏广告
- 用户可能在启动惯性中遇到广告弹出
- 双重广告策略增加误触概率

### 🟠 中等风险问题

#### 4. 卸载挽留页连续插屏

**问题场景**：
- UninstallResenActivity：第一次插屏
- UninstallConfirmActivity：第二次插屏

**风险分析**：
- 短时间内连续展示多个全屏广告
- 属于"高频但低价值"的用户行为
- 易被系统识别为噪声流量

#### 5. 缺乏用户操作完成检测

**当前拦截器**：
- ShowCountLimitInterceptor（日展示次数）
- ShowIntervalLimitInterceptor（展示间隔）
- ClickLimitInterceptor（点击次数）
- GlobalAdSwitchInterceptor（全局开关）

**缺失机制**：
- 无法检测用户是否完成明确操作
- 违反"任何广告只在用户完成明确操作后出现"的最佳实践

#### 3. 增加用户操作完成拦截器

**新增文件**：`UserActionCompletedInterceptor.kt`

```kotlin
class UserActionCompletedInterceptor : AdInterceptor {
    companion object {
        @Volatile
        private var lastActionCompletedTime: Long = 0L
        private const val ACTION_WINDOW_MS = 30_000L // 30秒有效窗口
        
        /**
         * 标记用户完成了明确操作
         * 在以下场景调用：
         * - 保存健康记录
         * - 完成测量
         * - 查看完整报告
         * - 设置提醒
         */
        fun markActionCompleted() {
            lastActionCompletedTime = System.currentTimeMillis()
            AdLogger.d("用户完成明确操作，允许展示广告")
        }
        
        fun hasRecentAction(): Boolean {
            val elapsed = System.currentTimeMillis() - lastActionCompletedTime
            return elapsed <= ACTION_WINDOW_MS
        }
    }
    
    override suspend fun intercept(context: Context, adConfig: AdConfig): AdResult<Unit> {
        if (!hasRecentAction()) {
            AdLogger.w("[${adConfig.getConfigKey()}] 用户未完成明确操作，跳过广告展示")
            return AdResult.Failure(
                AdException(
                    code = -10,
                    message = "用户未完成明确操作"
                )
            )
        }
        return AdResult.Success(Unit)
    }
}
```

### 方案 B：结构性优化方案

#### 1. 广告触发时机枚举

```kotlin
enum class AdTriggerTiming {
    PAGE_ENTER,      // 页面进入（不推荐）
    PAGE_EXIT,       // 页面退出
    ACTION_COMPLETE, // 用户完成操作（推荐）
    FEATURE_UNLOCK,  // 功能解锁
    CONTENT_VIEWED   // 内容查看完成
}
```

#### 2. 统一广告触发控制器

```kotlin
object AdTriggerController {
    
    suspend fun tryShowInterstitial(
        activity: Activity,
        timing: AdTriggerTiming,
        actionContext: String? = null
    ): Boolean {
        
        // 检查触发时机是否合适
        when (timing) {
            AdTriggerTiming.PAGE_ENTER -> {
                AdLogger.w("不推荐在页面进入时展示插屏")
                return false
            }
            AdTriggerTiming.ACTION_COMPLETE -> {
                if (actionContext == null) {
                    AdLogger.w("ACTION_COMPLETE 需要提供操作上下文")
                    return false
                }
                // 标记用户完成了操作
                UserActionCompletedInterceptor.markActionCompleted()
            }
            else -> { /* 其他时机的处理逻辑 */ }
        }
        
        // 统一调用插屏展示
        return when (val result = InterstitialAds.getInstance().displayAd(activity)) {
            is AdResult.Success -> {
                AdLogger.d("插屏广告展示成功，触发时机：$timing")
                true
            }
            is AdResult.Failure -> {
                AdLogger.w("插屏广告展示失败：${result.error.message}")
                false
            }
            AdResult.Loading -> false
        }
    }
}
```

```kotlin
// 为不同类型页面定义不同的广告策略
abstract class BaseAdStrategy {
    abstract fun shouldShowOnEnter(): Boolean
    abstract fun shouldShowOnExit(): Boolean
    abstract fun getRequiredUserActions(): List<String>
}

class RecordPageAdStrategy : BaseAdStrategy() {
    override fun shouldShowOnEnter(): Boolean = false
    override fun shouldShowOnExit(): Boolean = true // 仅在保存记录后
    override fun getRequiredUserActions(): List<String> = listOf("save_record")
}

class StatisticsPageAdStrategy : BaseAdStrategy() {
    override fun shouldShowOnEnter(): Boolean = false
    override fun shouldShowOnExit(): Boolean = true // 仅在查看完数据后
    override fun getRequiredUserActions(): List<String> = listOf("view_statistics")
}
```

```kotlin
fun shouldRequireUserAction(): Boolean {
    return configData?.let { config ->
        when (ChannelUserController.getCurrentChannel()) {
            ChannelUserController.UserChannelType.NATURAL -> 
                config.natural.interstitial.requireUserAction
            ChannelUserController.UserChannelType.PAID -> 
                config.paid.interstitial.requireUserAction
        }
    } ?: true
}

fun getActionWindowSeconds(): Int {
    return configData?.let { config ->
        when (ChannelUserController.getCurrentChannel()) {
            ChannelUserController.UserChannelType.NATURAL -> 
                config.natural.interstitial.actionWindowSeconds
            ChannelUserController.UserChannelType.PAID -> 
                config.paid.interstitial.actionWindowSeconds
        }
    } ?: 30
}
```

## 📈 效果监控

### 关键指标

1. **核减率监控**
   ```
   核减率 = (预估收益 - 最终收益) / 预估收益 × 100%
   ```
   - 目标：从当前 15-25% 降低至 5-10%

2. **展示质量指标**
   - 展示→结算保留率
   - 平均 eCPM 变化
   - 点击率（CTR）变化

3. **用户体验指标**
   - 应用评分变化
   - 用户留存率
   - 会话时长

### 监控实现

```kotlin
object AdQualityMonitor {
    
    fun trackAdShow(adType: String, triggerTiming: AdTriggerTiming) {
        ReportDataManager.reportData("ad_quality_show", mapOf(
            "ad_type" to adType,
            "trigger_timing" to triggerTiming.name,
            "user_action_completed" to UserActionCompletedInterceptor.hasRecentAction()
        ))
    }
    
    fun trackAdRevenue(adType: String, estimatedRevenue: Double, finalRevenue: Double) {
        val reductionRate = (estimatedRevenue - finalRevenue) / estimatedRevenue * 100
        ReportDataManager.reportData("ad_revenue_quality", mapOf(
            "ad_type" to adType,
            "estimated_revenue" to estimatedRevenue,
            "final_revenue" to finalRevenue,
            "reduction_rate" to reductionRate
        ))
    }
}
```

## 📝 总结

当前 HealthTracker 的广告策略存在明显的**误触风险**，主要体现在：

1. **返回键必弹插屏**：违反用户预期，产生大量无效点击
2. **页面进入即弹广告**：用户注意力未稳定时展示广告
3. **缺乏用户操作检测**：无法确保广告展示的合理性

**核心优化思路**：
- 从"页面生命周期驱动"转向"用户行为驱动"
- 严格遵循"用户完成明确操作后展示广告"原则
- 增加广告质量监控和远程配置能力

通过实施上述优化方案，预期可将核减率从当前的 15-25% 降低至 5-10% 的健康范围，同时提升用户体验和长期收益质量。
